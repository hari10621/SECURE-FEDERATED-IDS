      lead combines >= t shares to recover plaintext weights.
  * Web Platform:

    - Designed with modular abstraction (TenSEALCKKSBackend / NativeCKKSBackend).

SECTION 4: SECURITY, AUTHENTICATION & INTEGRITY MECHANISMS
================================================================================

4.1 Client Authentication:
  * Reference Paper:
    - Trusted Authority issues unique auth_token_i to each registered SDN client.
    - Server verifies auth_token_i in each communication packet.
  * Research Repository:
    - Generated a token at registration time, but NEVER checked it in update rounds.
  * Web Platform:
    - Implemented opt-in session token authentication via FLServer.authenticate_client().

4.2 Replay Protection:
  * Reference Paper:
    - Timestamp freshness window: |t_now - t_i| <= Delta_t_win.
  * Research Repository:
    - No timestamps or round-bound nonces in client updates.
  * Web Platform:
    - Implemented nonce cache tracking (client_id, round_index) pairs.
    - Rejects duplicate round submissions within the clock drift window (300s).

4.3 Integrity & Digest Verification:
  * Reference Paper:
    - SHA-256 hash computed over encrypted weights: H_i = SHA-256(E(Delta W_i)).
  * Research Repository:
    - SHA-256 computed on individual 4,096-slot chunks, but not bound to round index.
  * Web Platform:
    - SHA-256 weight digest binds floating-point weights and round_index:
      weight_digest = SHA-256(JSON(weights) : round=round_index).

4.4 Byzantine Fault Detection:
  * Reference Paper:
    - Evaluates token, timestamp, hash, and CKKS format; faulty clients placed in M.
    - Tolerates up to T_max = N/2 faulty clients; aborts round if |M| > T_max.
  * Research Repository:
    - Implemented a 3-sigma outlier heuristic on ciphertext serialized length.
  * Web Platform:
    - Re-implemented the 3-sigma outlier heuristic (opt-in via byzantine_check=True).
    - Explicitly documents that size-based heuristics are NOT a Byzantine security guarantee.
